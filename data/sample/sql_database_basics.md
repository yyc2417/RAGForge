# SQL 与数据库基础

## 数据库索引的原理是什么？

索引是帮助数据库快速定位数据的独立数据结构，主流关系库用 **B+ 树**：多叉平衡树，叶子节点存数据并用链表串联，范围查询友好。

**关键代价**：
1. 索引本身占存储空间
2. 写入（INSERT/UPDATE/DELETE）要同步维护索引，写放大
3. 联合索引遵循**最左前缀原则**：索引 (a, b, c) 只能命中含 a 的查询条件

哈希索引等值查询 O(1) 但不支持范围；ES 等搜索引擎用倒排索引支持全文检索。

## 事务的 ACID 是什么？

1. **原子性（Atomicity）**：事务内操作全成功或全回滚，靠 undo log 实现
2. **一致性（Consistency）**：事务前后数据满足完整性约束
3. **隔离性（Isolation）**：并发事务互不干扰，靠锁 + MVCC 实现
4. **持久性（Durability）**：提交后落盘不丢，靠 redo log（WAL 先写日志）实现

**隔离级别**（由低到高）：读未提交 → 读已提交 → 可重复读（MySQL 默认）→ 串行化。级别越高越安全，并发性能越低。常见异常：脏读、不可重复读、幻读。

## 数据库范式是什么？

范式是减少数据冗余的设计规则：
1. **1NF**：字段原子性，不可再分
2. **2NF**：消除非主键对联合主键的部分依赖
3. **3NF**：消除非主键之间的传递依赖

实际工程常**反范式化**：适度冗余（如订单表冗余商品名）换取读性能，避免多表连接。规范是手段不是目的。

## SQL 的 JOIN 有哪几种？

1. **INNER JOIN**：两表都匹配的行
2. **LEFT JOIN**：左表全量，右表无匹配填 NULL
3. **RIGHT JOIN / FULL JOIN**：对称/并集（MySQL 不支持 FULL JOIN）
4. **CROSS JOIN**：笛卡尔积

性能要点：连接字段要有索引；大表驱动小表；MySQL 的 JOIN 用 Nested-Loop（或 Block Nested-Loop / Hash Join 8.0+），不是哈希连接一统天下。

## 什么是慢查询优化的一般步骤？

1. `EXPLAIN` 看执行计划：type（ALL 全表扫描最差）、key（用了哪个索引）、rows（预估扫描行数）
2. 确认 WHERE / ORDER BY / JOIN 字段是否有合适索引
3. 避免 SELECT *，只取需要的列（覆盖索引可直接返回不回表）
4. 避免索引失效写法：对索引列用函数、隐式类型转换、前导 %
5. 大分页用游标（WHERE id > last_id LIMIT n）代替 OFFSET
