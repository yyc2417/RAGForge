# 交互与知识沉淀 · 实现设计

> 状态：Phase 1（会话 / clarify / 聊天 UI）与 Phase 2（多格式入库）已实现；Phase 3（优质库）与 Phase 4（评测 v2）待实现。
> 相关决策：ADR-007（固定 hybrid / 优质通道）、ADR-008（clarify 终止分支）。

## 1. 目标与边界

目标：在图外补齐多轮会话、clarify、多格式入库、反馈与知识沉淀，图本身保持无状态。

边界：

- 不做网页 URL 抓取、OCR、图片、复杂表格；
- 不做自动正确性校验；优质库靠人工移除；
- MVP 单进程、全量重建索引，不承诺生产级并发。

## 2. 总体架构

```text
Streamlit UI
  ├─ ConversationService（condense / 会话落盘 / 反馈）
  ├─ KnowledgeBaseService（demo + library 入库 / 重建）
  └─ LangGraph（7 主链路 + clarify）
        └─ Vector + BM25 + Hybrid（+ 可选 Reranker）

data/
  demo/       # 8 篇多格式演示语料，只读
  library/    # 上传 / 文件夹导入 / 后续优质库
  sessions/   # 会话 JSON
  feedback/   # 难例候选池（Phase 4）
```

## 3. 会话层

- `Session` / `SessionMessage` Pydantic 模型；
- `ConversationStore`：每会话一个 JSON，原子写，进程内锁；
- `ConversationService.prepare_query`：有历史时 condense，失败回退原问题；
- `record_assistant_state`：回答/澄清、来源、trace、指标落盘；
- 历史只注入最近 N 轮，按 token 预算从新到旧裁剪。

## 4. clarify

- `analyze` 输出 `needs_clarification / ambiguity_type / clarification_question`；
- 条件边进入 `clarify → END`；
- 不检索、不生成；下一轮带历史重新进图；
- `clarify_enabled` 可关闭；
- 评测单独建 10–20 个 case（Phase 4）。

## 5. 多格式入库

- 格式：MD / TXT / PDF / HTML / DOCX / CSV / JSONL；
- 解析统一为 `Document`，metadata 含 source / file_type / title / page / h1-h3 / row_index；
- CSV/JSONL 固定 `text/content` 约定；
- `KnowledgeBaseService` 汇总 demo + library，解析 → 切块 → 重建 Vector/BM25；
- 上传按内容哈希去重；文件夹仅允许项目 `data/` 下路径；
- demo 只读，library 可删除；
- 与图共享 retriever 对象，重建后图无需重建。

## 6. 优质库（Phase 3，已实现）

- 点赞后写 `library/quality/<message_id>.md`；
- metadata `source_type=qa_archive`；
- 检索增加加权 RRF 优质通道（`quality_weight=1.3` / `top_k=3` / `min_relevance=0.3` / `max_per_source=2`）；
- 侧栏优质库列表 + 移除按钮；
- 详细格式见 `docs/reference/quality-archive-format.md`。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| condense 失败 | 回退原问题 |
| 会话文件损坏 | 跳过并告警 |
| 单文件解析失败 | 记录错误，继续其他文件 |
| CSV 缺 text/content | 直接报错并列出列名 |
| JSONL 坏行 | 跳过并记录行号 |
| 文件夹越界 | 拒绝导入 |
| 重建失败 | 保留旧索引（调用方需提示） |
