# RAG 技术要点

## RAG 的标准流程是什么？

RAG（检索增强生成）三步：**索引**（文档解析 → 分块 → 向量化 → 入库）→ **检索**（用户查询向量化，取最相似的 top-k chunk）→ **生成**（把检索到的 chunk 作为上下文，让 LLM 基于它们回答）。

RAG 解决 LLM 的三个问题：知识过期（训练截止后的事实）、私有知识（模型没见过的内部文档）、幻觉（无依据编造——有据可查的上下文能显著抑制）。

## 分块（Chunking）有哪些策略？

1. **固定大小分块**：按字符/token 数硬切 + 重叠（overlap），简单但可能切断语义
2. **递归分块**：按分隔符层级（段落 → 句子 → 词）递归切分，尽量保住语义边界
3. **按结构分块**：利用 Markdown 标题、代码块等结构切分，chunk 携带标题路径作为上下文
4. **语义分块**：用 embedding 相邻句子相似度找语义断点，成本高但边界最准

分块大小的权衡：块太大 → 单块主题混杂、稀释向量表示且受 embedding 模型输入窗口限制；块太小 → 上下文不完整，检索命中也可能答不全。

## 混合检索为什么需要？

向量检索擅长语义相似，但对**精确关键词**（产品名、代码标识符、错误码）不敏感；BM25 等关键词检索正相反。两者互补。

**融合方法**：
1. **RRF（Reciprocal Rank Fusion）**：`score = Σ 1/(k + rank)`，只依赖排名不依赖分数尺度，鲁棒免调参
2. **加权分数融合**：各自归一化后加权，需要调参

生产系统普遍采用混合检索；评估显示混合召回通常不低于任何单路。

## 重排序（Reranker）解决什么问题？

检索阶段为速度用双塔/向量模型做粗排（从全库召回 top-50），重排序阶段用 CrossEncoder 对 query 和每个候选 chunk **逐对**精算相关性，输出更准的排序后取 top-5。

- 双塔：query 和 doc 分别编码，可离线建索引，快但精度低
- CrossEncoder：query 和 doc 拼接后一起进模型，交互更充分，精度高但只能在线逐对算

这就是「粗排 + 精排」两级架构。Reranker 通常不改变召回集合，但能显著改善排序指标（MRR / nDCG）。

## RAG 系统怎么评估？

**检索与生成分开评**：
1. 检索层：Recall@k（相关 chunk 是否进了 top-k）、MRR（相关 chunk 排在第几）、nDCG
2. 生成层：忠实度/ groundedness（回答是否忠于检索内容）、答案相关性、拒答准确率（对语料外问题是否诚实承认不知道）

数据集应包含可答题与**不可答题**（语料外问题，带 is_impossible 标记），并加入主题相近的干扰文档防止检索器"全捞"。LLM-as-judge 是生成层评估的主流做法。
